# v1.10 之后的续跑核心计划

> 日期：2026-08-07
> 状态：仅记录计划，**尚未开工**
> 当前暂停点：`v1.10.0` 两阶段续跑流水线完成并推送 `main` 后暂停；未打 tag、未发布 Release

这份计划只围绕 AgentPulse 的核心竞争力：**在不接管 Agent 的前提下，尽可能准确、及时、可证明地完成续跑。**
前端扩展、编排层和自治层不进入核心优先级。

## 1. 不变的产品边界

后续重构不得破坏以下约束：

1. AgentPulse 不启动、托管、代理或接管 Agent；会话所有权始终属于用户和原终端。
2. 定位不确定时宁可不投递；不能用吞吐或“成功率”换取误敲窗口的风险。
3. Rust 是检测事实、动作许可、协调状态和记账结果的唯一事实来源；前端只展示快照。
4. 窗口、剪贴板、键盘和真实输入继续全局串行；只读工作才允许跨会话并行。
5. 自动动作在真正输入前必须重验 lifecycle、运行状态、策略、额度、冷却、transcript 指纹和进程启动代际。
6. 任何“已投递”结论都必须区分 `Landed`、`Silent`、`Unverifiable`、`Failed`，不能把脚本返回成功冒充现实落地。

## 2. P0：先完成 v1.10 真实桌面验收

这是下一次恢复工作的第一项，不继续堆功能。按 `docs/manual-test.md` 第 13 节完成至少以下场景：

- 会话 A 进入最长 6 秒核验时，会话 B 的自动投递不被 A 阻塞；
- A 核验期间，用户对 B 手动续跑不等待 A；
- 同一会话在核验和记账完成前不会二次投递；
- stop 能取消尚未输入的自动动作，但不会抹掉已经真实回车的动作记账；
- 页脚 `pending / verifying` 与真实阶段一致，早退、失败和停止后都归零；
- macOS / Windows / Linux 与 tmux / screen 的原有定位安全边界不退化。

验收必须记录实际机器、系统版本、终端、Agent、通道、结果和失败日志；没有执行的项目继续保持未勾选，不能用单元测试代替实机结论。

## 3. P1：把一次续跑升级为显式 Attempt 状态机

候选版本：`v1.11`。目标不是增加功能，而是让每一次动作从生成到落账都有稳定身份和可恢复语义。

建议状态：

```text
Queued → WaitingForDelivery → Delivering → Verifying → Committing → Completed
                                  └──────────────→ Cancelled / Failed
```

计划内容：

- 为每次续跑生成 `attempt_id`，日志、内存状态和 SQLite 使用同一标识；
- 将 lifecycle epoch、session identity、动作快照和最终 outcome 绑定到 attempt；
- 明确每个状态允许的转换，拒绝重复提交和逆向转换；
- 进程崩溃或应用退出后，能够识别“已输入但未完成记账”的不确定 attempt，不盲目补敲；
- 将 pending/verifying 从两个裸计数扩展为由 attempt 状态归约出的只读快照；
- 保持 `delivery_lock` 与 session lease 的现有资源边界，不把状态机变成新的全局锁。

准入标准：状态转换有表驱动测试；重复 commit 幂等；崩溃恢复宁可标记不确定，也不能自动重复输入。

## 4. P1：让落地核验从固定轮询变成自适应证据窗口

候选版本：`v1.11` 或 `v1.12`，以实机数据决定是否值得实施。

当前最长 6 秒窗口安全但较粗。后续先采集事实，再考虑：

- 文件系统事件优先、低频轮询兜底，减少无意义唤醒；
- 依据 Agent、transcript 类型和历史落地延迟选择核验 deadline，但保留硬上限；
- 区分“文件增长”“结构化新事件”“仅 mtime 变化”，避免把无关写入当成 `Landed`；
- 记录投递到首个有效证据的延迟分布，用 P95/P99 而不是拍脑袋调整窗口；
- 无 transcript 的通道继续返回 `Unverifiable`，不能为了好看的成功率降级为默认成功。

准入标准：新算法在回放数据上不增加假阳性；实机尾延迟有可复现改善；CPU 与磁盘唤醒不高于当前实现。

## 5. P1：强化定位与进程身份评分，但不放宽拒绝门槛

目标是减少“明明能确认却找不到”的漏投递，而不是扩大盲敲范围。

- 将 PID、启动代际、TTY、pane、终端应用、窗口标题、工作目录拆成可解释的候选证据；
- 输出排序后的候选与拒绝原因，演练和日志展示 Rust 生成的事实；
- 对多窗口、多标签、PID 复用、终端重启和工作目录同名建立固定回放夹具；
- 只有唯一高置信候选才允许投递；并列、冲突或证据不足仍拒绝；
- `auto_follow_latest` 继续是显式高风险开关，默认关闭。

准入标准：定位测试矩阵扩大但“错误窗口零容忍”不变；所有新增拒绝/提示文案保持中英双语。

## 6. P2：并发与故障注入测试

在继续调整协调器前，补足无法靠普通单元测试覆盖的竞态：

- 使用可控时钟和 fake resumer 验证 stop/start、配置热更新、冷却到期和 transcript 突变；
- 对 `ResumeQueue + ResumeRegistry + delivery_lock` 做随机动作序列或 property test；
- 注入 deliver panic、verify 超时、SQLite 失败、通知失败，确认 lease 与阶段状态总能归还；
- 压测大量 session 时的任务数量、队列上界、公平性和内存占用；
- 增加“同 session 永不并发输入”“不同 session 核验可重叠”“真实输入全局不重叠”三个并发断言。

准入标准：测试可在 CI 稳定复现，不依赖真实桌面；真机测试继续单独记录，不伪装成 CI 覆盖。

## 7. 暂不进入计划

- v2.0 编排和 v2.1 自治：与非侵入守护定位冲突，继续搁置；
- 为追求速度并发操作多个桌面窗口或共享剪贴板：明确禁止；
- 前端自行预测或重算续跑许可：明确禁止；
- 在没有 transcript/窗口证据时把 `Unverifiable` 美化成 `Landed`：明确禁止；
- 未经用户确认的 tag、Release 或自动更新发布：不做。

## 8. 下一次恢复工作的顺序

1. 读取本文件、`specs/v1.10_resume_pipeline_design.md` 和 `docs/manual-test.md`；
2. 确认 `main` 与 GitHub CI 状态，不假设上次推送已经通过；
3. 先执行 v1.10 P0 真机验收并记录证据；
4. 根据实测瓶颈，在“Attempt 状态机”和“自适应核验”之间选择一个作为下一版唯一核心主题；
5. 写设计规格与失败不变式，再改代码；
6. 保持每阶段本地门禁、提交、推送，但未收到明确要求前不打 tag、不创建 Release。
